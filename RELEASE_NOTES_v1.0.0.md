# 👻 GhostTrace AI v1.0.0 — Stable Release Notes

> *"The machine remembers. Now it has a story to tell."*

We are proud to present **GhostTrace AI v1.0.0**, the first stable release of our local-first digital archaeology and forensic narrative platform. GhostTrace AI exhumes abandoned codebases, crash logs, forgotten TODOs, and terminal histories, synthesizing verifiable ground-truth evidence, technical forensic hypotheses, and atmospheric gothic storytelling entirely on your local machine.

---

## 🌟 Core Highlights

### 1. Evidence vs. Imagination (3-Tier Epistemic Separation)
- **Tier 1 — Verified Evidence (Ground Truth):** Facts derived exclusively from deterministic parser outputs (TODOs, panics, timestamps, file boundaries). Guaranteed zero AI hallucinations.
- **Tier 2 — Forensic Interpretation (AI Hypotheses):** Technical deductions generated by the local language model, clearly flagged with epistemic notices ("Plausible technical hypotheses, not legal proof").
- **Tier 3 — Fictional Narrative (Spectral Storytelling):** Atmospheric horror roleplay channeled through distinct personas (*The Midnight Committer*, *The Panic Core*, *The Deprecated Dependency*, *The Digital Archaeologist*), explicitly identified as fiction for entertainment.

### 2. Privacy-First Redaction Shield
- Automatically sanitizes API keys, GitHub tokens, Bearer authorization, passwords, database connection URIs, RSA/EC private keys, JWTs, and local Windows/Unix user paths.
- Redaction previews display static `[REDACTED]` markers and `⟦REDACTED_ECTOPLASM⟧` tokens—never exposing raw credential fragments in UI tooltips, logs, metadata, or exported reports.
- Redaction occurs client-side before any payload is submitted to the local inference engine.

### 3. Digital Memory Explorer & Strict Limits
- Ingest and analyze multiple files within explicit, audited boundaries:
  - Maximum **30 files**
  - Maximum **2 MB aggregate size**
  - Maximum **500 KB per individual file**
- Automatically rejects binary files (null-byte inspection) and empty artifacts.
- Line-level manifest mapping preserves exact file-relative citation arithmetic across multi-file directories.

### 4. Haunted Terminal Forensics (Inert Parsing Guarantee)
- Analyzes shell history (`.bash_history`, `.log`, PowerShell dumps) strictly as inert text strings.
- Detects desperation command loops, exit code failures (`137` OOM, `139` Segfault), and destructive signatures (`rm -rf`, `drop database`, `dd`).
- **Zero Command Execution:** Contains zero calls to `eval()`, `new Function()`, `child_process`, or shell execution.

### 5. Resilient Local Ollama & Gemma Streaming
- Full streaming support for local open-weight models via Ollama (`http://localhost:11434`).
- Split JSONL network chunk buffering reassembles broken records across arbitrary stream boundaries.
- Trailing unclosed JSONL record decoding prevents dropped final tokens.
- Dynamic **inactivity timeout** resets on every emitted token chunk, accommodating long inferences without premature abortion.
- Automatic, graceful fallback to a grounded **Offline Simulation Engine** with clear truth-in-labeling badges (`🟡 Offline Simulation Engine`) and a one-click "Retry Ollama" recovery button.

### 6. Interactive Citations & Anomaly Protection
- Interactive `📍 Line` badges allow one-click jumping and highlighting in the Source Code Evidence Crypt.
- Out-of-bounds line numbers or references to missing files trigger prominent amber `Unverified Citation Warning` banners and suppress false line highlighting.

### 7. Markdown Autopsy Dossier Export
- One-click export of structured `ghosttrace_<filename>_dossier.md` reports preserving verified ground-truth facts, forensic deductions, spectral narratives, engine attribution, and sanitized text.

## 🚀 Installation & Quickstart (Windows)

### Prerequisites
- [Node.js](https://nodejs.org/) v18+ (tested on Node.js v24.21.0)
- [Git](https://git-scm.com/)
- *(Optional for AI inference)* [Ollama](https://ollama.com/) with Gemma:
  ```powershell
  ollama run gemma4:e4b
  # Or a lighter model for faster initial token generation:
  ollama run qwen3:1.7b
  ```

### 1-Click Startup
- Double-click `start.bat` to launch the dev server and open `http://localhost:5173/` in your browser.
- Double-click `stop.bat` to terminate the server.

### Terminal Launch
```powershell
# Install dependencies from committed lockfile
npm.cmd ci

# Launch development server
npm.cmd run dev

# Run automated tests
npm.cmd test

# Build production bundle
npm.cmd run build

# Preview production build
npm.cmd run preview
```

## ⚠️ Security, Privacy & Known Limitations

> [!WARNING]
> **Operational Security Notice:**
> 1. **Zero External Data Transmission:** GhostTrace AI operates 100% on your local machine. No code, logs, backtraces, or user inputs are uploaded to external cloud services or telemetry endpoints.
> 2. **Heuristic Redaction Boundaries:** The Redaction Shield utilizes deterministic regular expressions for standard credential formats (AWS keys, OpenAI/GitHub tokens, JWTs, Bearer headers, database connection strings, RSA/EC private keys, local user home paths). Obfuscated, custom proprietary formats, or base64-encoded secrets may evade detection. **Never import or paste active production root credentials.**
> 3. **Model Cold-Start Latency:** Loading large models (6.5GB+) on CPU or lower-tier GPUs may exceed 60 seconds of initial load time before emitting the first token, triggering the automatic fallback to the local simulation engine. For faster startup, lighter models such as `qwen3:1.7b` or `gemma2:2b` are recommended.
> 4. **Truth in Labeling:** AI interpretations are probabilistic technical deductions, not legal testimony. Fictional narratives are creative roleplay entertainment and must never be treated as verified evidence.

## 🔄 Upgrade & Rollback Guidance

### Upgrading from `v1.0.0-rc.1`
GhostTrace AI `v1.0.0` is a stable, drop-in release with no breaking schema or architectural changes. Cleanly pull or checkout the tag and run:
```powershell
npm.cmd ci
npm.cmd run build
```

### Rollback Plan
If an environment-specific issue occurs in production:
1. Revert to the previous verified release candidate commit:
   ```powershell
   git checkout v1.0.0-rc.1
   npm.cmd ci
   npm.cmd run build
   ```
2. If a patch is required, develop the fix against a new branch and release `v1.0.1`. Never rewrite or force-push shared release tags.
